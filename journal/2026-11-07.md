# 2026-11-07

*the day the board existed and the graph under it*

## what was decided, and by what

started as "jamflow", became "flowby" within the hour, which is the cheapest rename of the project. the name does not matter yet; the ordering does.

the ordering came from reading the two products in the brief properly instead of from the summary of them. vectary canvas says, in as many words, *combine presets as your idea evolves*, and fuser says *one click, whole workflow* and *every step stays visible in the graph*. those two sentences together are the product, and they also kill a wrong version of it: a preset that runs and hides. so the first file written was not a component, it was `presets.py`, and the first rule was that a preset is a subgraph that gets spawned and left where it can be found.

the second decision was the palette. four colours, and depth and mask ride green as roles, because six colours is a legend nobody reads. the refusal that came with it is the one worth keeping: **nothing coerces**, so red becoming blue happens in a node called `render.frames` and not in a rule.

## what surprised the plan

three things, all in the code rather than the design.

**a choice slider defaulting to a number passes every reading eye and fails at import.** the first run of `flowby plan --preset animate-composition` died on `motion is 1`, because the slider's default was `1` and its choices were words. that is now refused in `Slider.__post_init__`, which means the class catches the typo instead of a user.

**style transfer needs two assets and the preset model had nowhere to say so.** the first version wired the element into `read.reference` and left `paint.content` dangling, which compiled into a refusal naming a port instead of a gesture. the fix is `Slot`: a preset may declare an input it cannot fill, spawn incomplete, and refuse with the sentence that is the instruction. it also gave the two views their first genuinely equal job, because "this needs a second image" is a drag in the node view and nothing at all in the spatial one.

**detaching a preset and reapplying the same one is refused, and that is correct.** the frame is showing the mesh the loose nodes made, the preset reads green, so it says so and offers the preset that would get back to green. the test that asserted a fork had to learn the same thing, which is a good sign: the refusal was right before the test was.

## what is not true yet

no model has run. `worker.py` names every op it cannot do and refuses, and `--simulate` exercises the pipe with real hashes over bytes that are not pixels. the readme says that in a table, and the table is the most important page in the repo, because the alternative is a tree that claims to work and cannot be debugged.

the react binding in `web/src` has never been built: there is no `node_modules` here. the camera maths it calls does have a test, and it passes, which means the hard half of a hybrid board is at least arithmetic somebody checked.
