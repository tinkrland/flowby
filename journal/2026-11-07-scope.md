# 2026-11-07, scope

*their benefits table was our architecture with one row missing*

the owner's correction was the useful part: it is a node canvas too, the nodes are just premade. and the two screenshots he sent are the argument for that, because they show the catalogue organised by **surface** rather than by model (texturing and materials, surface details, lighting and environments, design and ideation) with four named effects in the seam family alone: crease, stitch, emboss, deboss.

then the benefits table, which is three rows:

| less prompting | preset chaining | design dna matching |
| --- | --- | --- |
| a curated task block | stack presets on the same asset | transfer a design language across layouts |

the first two were already rules here. the third was a **scope**, and it had been hiding in a phrase nobody reads twice: *lighting and environments, modified instantly across your infinite board*. a lighting style is not a property of one frame. it is a property of the shoot.

## what a board preset is

`shared_seam` and `tail_port` on a preset, `apply_shared` on a scene. one head node, one tail node per frame, and the wire from the head into every tail is a real wire in the graph, so the pipeline view shows one line fanning into three instead of three separate reads.

the numbers are the argument again: three frames, one `light.study` at 0.6 and three `light.grade` at 0.9 each, so 3.3 minutes rather than 4.5. the head is genuinely one node, which is checkable in the graph rather than asserted in prose, and a frame that joins later reads the same head instead of paying for another one.

two things had to change to make that safe, and both were wrong in ways the tests caught rather than the design:

* **`instance.sink` stopped being enough.** a board instance has one sink *per frame*, so `sinks` is a map, and `variant_count` had to ask which frame before it could answer. an instance that points one frame at one node is still the common case, and the map keeps it cheap.
* **`apply` had to route board presets through the shared path**, or a single-frame application produced a graph with the frame wired to the head and nothing wired to the tail. one way to build the shape, not two that disagree.

## the smaller things

**a choice slider carries a payload, and i broke it for an hour.** `("neon", "neon, wet streets")` is (what you see, what the node receives), which is right for a prompt fragment and wrong for a mode name. the fix was not in the slider, it was in `surface-detail`: identity pairs, so `deboss` reaches the node as `deboss`. the description moved into the control's `means`, which is where a sentence about four options belongs.

**the standalone graph test had to be taught about scope.** every preset was checked as a closed template, and a board preset is deliberately not closed: it takes frames from outside. so the fixture stands one frame in, and the test still proves what it was written to prove, that no preset disagrees with itself.

## what is still not true

no model has run, and the new presets do not change that. `light.study`, `light.grade`, `mesh.read` and `mesh.detail` are named in the worker's refusal list like every other op. `studio-light` and `surface-detail` are `designed`, not `verified`, and the readme's table says so.

the next honest thing to build is the frame that draws a *fan*: a shared light means one frame changing is fine, but six variants means a contact sheet, and `web/` still has no tldraw shape for anything.
